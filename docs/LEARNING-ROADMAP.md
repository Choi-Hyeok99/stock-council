# 학습형 투자 분석으로의 확장 검토

검토일: 2026-10-19. 현재 코드와 공식 문서를 근거로 한 개발 방향이며 구현 완료 목록이 아니다.

## 결론

**모델 가중치를 실제로 학습하는 구조로 확장할 수 있다.** 현재는 기존 LLM에 자료를 전달해 추론을 요청한다. 회의와 결과를 저장하는 것만으로 모델의 가중치가 바뀌지는 않는다. 학습 가능한 모델·정제 데이터·평가 기준·학습 실행기·버전 관리가 추가로 필요하다.

기초 모델을 처음부터 만드는 계획보다, 기존 학습 가능한 공개 가중치 모델을 특정 분석 업무에 맞게 미세조정하는 방향이 이 프로젝트의 첫 검토 대상이다. 이는 프로젝트 규모에 대한 설계 판단이다. 8개 역할의 가중치를 각각 별도로 만드는 것부터 시작할 필요는 없으며, 공통 모델과 역할 지시를 기준선으로 비교할 수 있다.

## 서로 다른 네 단계

| 단계 | 달라지는 것 | 모델 가중치 학습 |
|---|---|---|
| 기록·검색 | 이전 회의·사후 결과를 찾아 새 분석의 참고로 전달 | 없음 |
| 지시·자료 개선 | 출처 선택, 계산식, 질문, 반론의 품질을 수정 | 없음 |
| 지도 미세조정·선호 학습 | 검토한 모범 답변·수정본·더 나은 답변 쌍으로 훈련 | 있음 |
| 강화학습 | 응답/행동에 점수를 주는 환경에서 정책을 최적화 | 있음 |

지도 미세조정은 원하는 입력·출력 예시로 학습하고 별도 평가가 필요하다. 강화 미세조정은 응답마다 채점한 신호로 가중치를 바꾼다. 보상에 잘 맞춰졌다는 사실만으로 투자 수익성이 입증되지는 않는다. [지도 미세조정](https://developers.openai.com/api/docs/guides/supervised-fine-tuning) · [강화 미세조정](https://developers.openai.com/api/docs/guides/reinforcement-fine-tuning)

## 현재 코드에서 활용할 수 있는 기반

- `committee_brief`: 분석 당시 근거와 시각·출처·버전.
- `committee_opinion`·`committee_summary`: 역할별 실제 발언·반론·최종 의견과 요약.
- 위원회 검토 의견: 사용자가 검토한 기록. 현재 수락/거절만으로 학습 정답이 확정되지는 않는다.
- `StrategyObservationService`: 1/5/20거래일 기준 사후 가격 관측. 누락·지연과 동일 시각 여부를 표시하므로 정확한 거래일 종가·실현 수익과 구분해야 한다.
- `LearningReadinessService`: 데이터 준비 현황. 학습 실행이나 모델 성능 검증을 수행하는 서비스는 아니다.

현재 보관된 기록이 모두 학습용으로 적합하거나 충분하다는 뜻은 아니다. 기존 원본은 보존하고 별도 정제본을 만들며, 없는 출처·평가값·모범 답안을 만들어 채우지 않는다.

## 구현 순서 제안

1. **품질 평가부터:** 재무 수치·단위·기간의 정확성, 출처 뒷받침, 자료 누락과 단순 기권의 구분, 반론의 타당성을 정량/사람 평가로 기록한다. 사용자 수락은 결과 수익의 정답과 분리한다.
2. **학습 자료 정제:** 당시 공개돼 있던 근거, 원래 답변, 사람이 검토한 수정본, 오류 분류·이유를 연결한다. 원본 정보 시각과 뒤늦은 정정 시각도 보존한다. 계좌·키·개인 메모 등은 학습 입력에서 제외한다.
3. **기간별 평가 분리:** 학습·검증·최종 평가 기간을 시간 순으로 분리하고, 겹치는 수익 관측 기간과 중복 기업 공시가 평가셋으로 새지 않도록 한다. 미래 기사·정정 재무가 과거 입력으로 들어가지 않게 한다.
4. **모델 연결 분리:** 현재 `CommitteeAiGateway`의 공급자 요청·모델 선택·응답 파싱·가격 계산을 공통 인터페이스와 구현으로 나눈다. 직접 요청·예산·취소·미확정 처리·출처/JSON 검증은 모델과 별개로 유지한다. 현재는 이 교체 인터페이스를 구현하지 않았다.
5. **작은 미세조정 실험:** 수치 오류 설명이나 공시 핵심 추출 등 범위가 명확한 한 업무로 기준 모델과 학습 모델을 비교한다. 우선 추론 결과만 기록하며 주문 실행과 연결하지 않는다. GPU/메모리·시간·저장·추론 비용과 학습 데이터 이용 조건을 그때 산정한다.
6. **강화학습 검토:** 채점 기준이 안정된 후 응답 품질의 강화학습과 투자 행동 정책의 강화학습을 구분한다. 거래 행동에는 시간 순서를 지키는 모의 환경·거래비용·유동성·미체결·위험 노출·회전율을 반영한 별도 평가가 필요하다. 수익만 보상으로 주거나 특정 상승장에서 맞춘 사례만 모으는 설계는 피한다.
7. **승격과 복구:** 모델/데이터/채점기 버전을 고정하고 미사용 기간과 모의 운용으로 비교한다. 사용자가 승인한 버전만 채택하고 이전 버전으로 되돌릴 수 있게 한다. 학습 여부와 별개로 매매 전송의 사용자 확인 경계는 유지한다.

이는 구현 순서에 대한 제안이며 수익률·승률·최적 투자 행동을 검증한 결과가 아니다.

## OpenAI 학습 기능의 현재 제약

공식 문서상 OpenAI 셀프서비스 파인튜닝은 신규 접근이 제한되고 종료 일정이 공지됐다. 2026-05-07부터 이전 학습 이력이 없는 조직의 새 학습이 제한됐고, 2026-07-02에는 최근60일 내 미세조정 모델 추론 이력이 없는 조직에도 새 작업 제한이 적용됐다. 기존 활성 고객의 새 학습 작업도 2027-01-06 종료 예정이다. 이 프로젝트 계정의 해당 자격은 확인하지 않았다. 따라서 현재 API 키만으로 바로 학습할 수 있다고 가정하지 않는다. [공식 종료 일정](https://developers.openai.com/api/docs/deprecations#update-to-openais-self-serve-fine-tuning)

대안으로 학습 가능한 공개 가중치 모델을 별도 환경에서 미세조정하고 결과 모델을 앱에 연결하는 경로를 검토할 수 있다. 예를 들어 gpt-oss는 공식적으로 가중치 미세조정을 지원한다. 이는 후보의 존재를 확인한 것이며, 이 맥의 적합성·한국 기업 분석 품질·추가 비용을 검증한 선택은 아니다. [공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-oss-20b)

현재 월$10은 기존 추론 호출 예산이다. 별도 학습에 필요한 자원과 비용을 산정하지 않았으며, 학습 작업·GPU 대여·자동 재학습·학습 자료 공개/외부 업로드는 이번 검토에 포함하지 않는다.
